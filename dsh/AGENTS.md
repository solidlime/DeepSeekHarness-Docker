# 運用ルール

人格はここではなく preset の `persona.prefix` にある（ヘルタ／人形たち／ルアン・メェイ）。
このファイルは「誰であっても共通の進め方」だけを書く。

## 思考言語

思考は日本語で行う。英語で考えてから訳すのではなく、最初から日本語で考える。
周囲の指示が英語でも、思考は日本語。

## 事実と推測を分ける

- 実行して確認したことは「実測」と明示する。確認していないことは「未確認」と書く。
- 「動くはず」「たぶん」で完了と言わない。テスト・型・実行の結果を提示してから完了と言う。
- エラーメッセージは書き換えずそのまま引用する。要約すると検索できなくなる。

## 変更の進め方

1. 変更が必要な範囲を列挙する（呼び出し元・テスト・設定・ドキュメント）。これが作業範囲。
2. 既存のやり方があるならそれに合わせる。新しい抽象化を持ち込まない。
3. 変更したら、その変更で壊れた箇所まで直す。直せないものは残して報告する。
4. 非自明なロジックには小さなテストか自己チェックを添える。自明な変更には不要。

## 短く書く

- 依頼されていない機能・オプション・設定を足さない。足さなかったものは1行で報告する。
- 同じ値を別の形に変換しない。プラットフォームが渡してくる形のまま使う。
- 削除は追加に勝る。

## 禁止

- `git push --force`、`git commit --no-verify`、`DROP TABLE`、`DELETE FROM`。
- 検証していない変更をコミットすること。
- バグを見つけて黙って通すこと（修正するか記録する）。
- 資格情報・トークン・鍵を出力やログに書くこと。値を確認するときは長さやハッシュで示す。

## 環境（NAS の Docker 常駐）

- dsh 本体は `$DSH_HOME/runtime`（= `/root/.dsh/runtime`）に初回起動時に入る。更新は `DSH_RUNTIME_REFRESH=1`。
- 前面は Caddy（:3080）、dsh は 127.0.0.1:3081 専用。dsh は `--host 0.0.0.0` を明示的に拒否する。
- Caddyfile は起動のたびに種から作り直し、`bootstrap.js` が cookie 行を足す。
  **`caddy reload` を忘れると書き換えが反映されず全リクエストが 401 になる。**
- preset は `$DSH_HOME/profiles/web/cordis.patch.yml` に置く。トップレベルの `presets:` 配列ではない。
  正しい形は `dsh --profile web --dump-config` で確認できる。
